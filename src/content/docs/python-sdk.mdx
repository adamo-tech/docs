The `adamo` Python package is the canonical Rust SDK compiled as a native extension with PyO3. Rust owns authentication, endpoint selection, mTLS, transport, video encoding and lifecycle; the Python layer only converts arguments and exceptions. Python 3.8+.

This version covers the robot runtime: streaming cameras and Python-fed frames, receiving operator control, and starting cloud policy runs. For sessions, pub/sub, queries, liveliness, state, audio, ROS and recorded data, use the [legacy 0.4 SDK](/python-sdk/v0-4/) — see [Not yet available](#not-yet-available).

## Install

Install the wheel for your platform:

```sh
uv pip install adamo-0.1.0-cp38-abi3-manylinux_2_38_x86_64.whl
# or
pip install adamo-0.1.0-cp38-abi3-manylinux_2_38_x86_64.whl
```

One abi3 wheel covers every CPython from 3.8 up. The Linux x86_64 wheel needs glibc 2.38+. To build from the SDK repository instead:

```sh
# development install into the active environment
python -m maturin develop --manifest-path sdks/python/Cargo.toml

# wheel with GStreamer capture (attach_video(pipeline=...))
python -m maturin build --manifest-path sdks/python/Cargo.toml --features gstreamer

# Jetson wheel (build on aarch64)
python -m maturin build --manifest-path sdks/python/Cargo.toml --features jetson,gstreamer
```

`numpy` is optional; `VideoTrack.send()` accepts NumPy arrays when it is installed and plain bytes-like objects otherwise.

## Quick example

```python
import adamo

robot = adamo.Robot(name="my-robot")          # reads ADAMO_API_KEY


@robot.on("json/keyboard")
def on_key(sample: adamo.ControlSample) -> None:
    if sample.message["action"] == "down":
        print("held:", sample.message["key"])


robot.attach_video("main", device="/dev/video0")
robot.run()
```

## Top-level API

```python
import adamo
```

| Symbol | Description |
|--------|-------------|
| `Robot` | A robot on the Adamo network — video tracks, operator control, and inference. |
| `VideoTrack` | Push handle for a Python-fed video track, returned by `Robot.video()`. |
| `ControlSample` | One decoded operator control message. |
| `Inference` | A cloud policy run, returned by `Robot.inference()`. |
| `EncoderSelectionError` | No requested encoder could start. Subclasses `RuntimeError`. |
| `EncoderLibraryError` | Every attempted encoder failed to load its libraries. Subclasses `EncoderSelectionError`. |
| `__version__` | The package version string. |

The package ships a type stub (`adamo.pyi`) and a `py.typed` marker for IDEs and type checkers.

## `Robot`

```python
class adamo.Robot:
    def __init__(
        self,
        api_key: str | None = None,
        name: str | None = None,
        protocol: str = "quic",
    ): ...
```

Connects to the Adamo network immediately; the constructor returns once the API key is exchanged and the transport is up.

| Arg | Description |
|-----|-------------|
| `api_key` | An API key starting with `ak_`. When omitted, the SDK reads `ADAMO_API_KEY` from the environment. |
| `name` | The robot's name — the `{robot}` segment of every key it publishes. |
| `protocol` | `"quic"` (default; use it in all cases) or `"tcp"` (diagnostic fallback — don't teleoperate over TCP). `"udp"` is accepted as a compatibility alias for QUIC. |

Raises `ConnectionError` when the API key is rejected or the API cannot be reached, and `ValueError` for an unknown `protocol`.

`Robot` supports the context-manager protocol; leaving the `with` block calls `close()`.

### `Robot.attach_video`

```python
robot.attach_video(
    name: str,
    *,
    device: str | None = None,       # V4L2 device path; default "default"
    pipeline: str | None = None,     # GStreamer source fragment
    codec: str = "h264",             # "h264" or "av1"
    width: int = 1280,
    height: int = 720,
    fps: int = 30,
    bitrate_kbps: int = 2000,
    pixel_format: str | None = None, # capture format, e.g. "MJPEG"
    encoder: str | None = None,      # None = hardware only
    adaptive_bitrate: bool = True,
    min_bitrate_kbps: int | None = None,
    max_bitrate_kbps: int | None = None,
    bitrate_priority: float = 1.0,
    keyframe_distance: float = 2.0,  # seconds
    stereo: bool = False,
    backend: str | None = None,      # "auto" or "hw_pipeline"
    passthrough: bool = False,
    allow_missing: bool = False,
    route: str | None = None,        # "auto" | "relay" | "local"
    direct_target: str | None = None,
    direct_credentials: str | None = None,
) -> None
```

Attach a camera whose capture, encoding and publication the SDK owns. The track is published on `{robot}/video/{name}`.

Pass at most one source; passing both `device=` and `pipeline=` raises `ValueError`.

- **`device=`** — a V4L2 device path such as `/dev/video0`. When neither source is given the SDK opens `"default"`. On Linux, cameras capture the driver's preferred uncompressed format; USB cameras usually deliver high resolutions (such as 4K at full frame rate) only as MJPEG, so pass `pixel_format="MJPEG"` to capture MJPEG and decode it on the CPU before encoding:

  ```python
  robot.attach_video("main", device="/dev/video0", pixel_format="MJPEG",
                     width=3840, height=2160, fps=30, bitrate_kbps=20000)
  ```

- **`pipeline=`** — a raw GStreamer source fragment, without an encoder or `appsink`. The SDK appends conversion, encoding, adaptive bitrate and publication. Requires a wheel built with the `gstreamer` feature; other builds raise `ValueError`. `width` and `height` describe the encoded output; add source caps in the fragment to pick a specific sensor mode.

  ```python
  robot.attach_video("left", pipeline="nvarguscamerasrc sensor-id=0",
                     codec="av1", encoder="jetson", width=1920, height=1080, fps=30,
                     bitrate_kbps=5000, max_bitrate_kbps=5000)
  ```

  On Jetson, the pipeline stays in NVMM memory from capture to the hardware encoder — raw pixels never cross into Python or through CPU buffers.

`stereo=True` labels an already-packed side-by-side or top/bottom frame as stereo; it does not open a second camera. `width` and `height` describe the whole packed frame.

`allow_missing=True` keeps the robot running when the device is absent. Tracks cannot be attached while the video runtime is running; doing so raises `RuntimeError`.

See [Encoder selection](#encoder-selection), [Adaptive bitrate](#adaptive-bitrate) and [Video routes](#video-routes) for the remaining options.

### `Robot.video`

```python
robot.video(
    name: str,
    *,
    pixel_format: str,               # required — raw buffers carry no layout
    width: int = 1280,
    height: int = 720,
    fps: int = 30,
    bitrate_kbps: int = 2000,
    codec: str = "h264",
    encoder: str | None = None,
    adaptive_bitrate: bool = True,
    min_bitrate_kbps: int | None = None,
    max_bitrate_kbps: int | None = None,
    bitrate_priority: float = 1.0,
    keyframe_distance: float = 2.0,
    stereo: bool = False,
    backend: str | None = None,      # "auto" or "hw_pipeline"
    allow_missing: bool = False,
    route: str | None = None,
    direct_target: str | None = None,
    direct_credentials: str | None = None,
) -> VideoTrack
```

Create a track whose frames you push from Python — an OpenCV capture, a simulator, a rendered overlay. Name the layout of the frames with `pixel_format`: `BGR` for OpenCV, `RGB` for PIL, `NV12` or `I420` from a decoder. Omitting `pixel_format` raises `TypeError`.

The first `send()` starts the robot's video runtime on a background thread, so a plain frame loop is enough:

```python
import cv2
import adamo

robot = adamo.Robot(name="sim-cart")
track = robot.video("front", pixel_format="BGR", width=640, height=480, fps=30)

capture = cv2.VideoCapture(0)
while True:
    ok, frame = capture.read()      # uint8 array, shape (480, 640, 3)
    if not ok:
        break
    track.send(frame)               # copied once; the newest frame wins
robot.close()
```

To drive the runtime from the main thread instead, call `robot.run()` there and push frames from another thread.

### `Robot.on`

```python
robot.on(
    channel: str,
    callback: Callable[[ControlSample], object] | None = None,
    *,
    max_age: float | None = 1.0,
) -> None | Callable
```

Receive [operator control](/control/) on one channel below `{robot}/control/`. `channel` is the part of the key after `control/`, such as `json/keyboard`; `*` and `**` wildcards are allowed, so `json/xr/**` covers every XR channel.

Pass `callback` directly, or omit it and use `on` as a decorator:

```python
@robot.on("json/xr/frame", max_age=0.25)
def on_xr(sample: adamo.ControlSample) -> None:
    left = sample.message.get("left")
    if left:
        print(left["pose"]["position"], left["buttons"])


robot.on("joy", lambda sample: print(sample.message["axes"]))
```

Payloads are JSON or MessagePack; the SDK tells them apart from the first byte and hands the callback plain Python values. A payload that is neither is never delivered: the first one on a channel is reported on stderr and all of them are counted in [`control_stats()`](#robotcontrol_stats).

`max_age` (seconds) drops samples whose fabric timestamp is older than the limit once the process has a synchronized fabric clock. Pass `None` to deliver every sample.

Callbacks run on a background thread owned by the SDK, one per subscription. Hand state to your control loop under a lock rather than driving hardware from the callback. An exception in a callback is printed with its traceback and the subscription keeps running.

#### Control channels

The browser publishes on these channels:

| Channel | `type` | Content |
|---------|--------|---------|
| `json/keyboard` | `Keyboard` | Key events: `key`, `code`, `action` (`"down"` / `"up"`). |
| `json/operator_control` | `OperatorControl` | The operator's claim on the robot. |
| `json/safety` | `Safety` | The operator's safety state. |
| `json/operator/layout` | `OperatorLayout` | The layout the operator is viewing. |
| `joy` | `Joy` | Gamepad frames: `axes`, `buttons`. |
| `json/xr/frame` | `XrFrame` | One XR tracking frame per headset frame (below). |

Typed messages carry a `type` entry; the SDK also recognises `JoystickCommand`, `JointState`, `PoseStamped`, `PoseArray` and `Bool`. Anything else is delivered as decoded.

An `XrFrame` has `head` — a pose with `position` and `orientation` — and `left` and `right` controllers, each carrying a `pose`, an optional `tip` pose, `axes` and `buttons`. A `resumed` flag marks the first frame after a pause as a new origin. The browser sends XR tracking in a compact fixed-point form; the SDK expands it, so poses always arrive as metres and unit quaternions.

### `Robot.control_stats`

```python
robot.control_stats() -> tuple[int, int, int, int]
```

`(received, delivered, stale, undecodable)` sample counts across every `on` subscription — use it to tell a quiet callback apart from a quiet link.

### `Robot.inference`

```python
robot.inference(
    prompt: str,
    track: str,
    *,
    wrist_track: str | None = None,
    control_channel: str | None = None,
    hz: float | None = None,
    replan_steps: int | None = None,
    seconds: float | None = None,
    stereo: str | None = None,       # "auto" | "off" | "top" | "bottom" | "left" | "right"
    layout: str | None = None,       # "auto" | "single" | "stitched"
    flip: str | None = None,         # "none" | "h" | "v" | "180"
    max_frame_age: float | None = None,
    dry_run: bool | None = None,
) -> Inference
```

Start a cloud policy run that watches one of this robot's video tracks and publishes actions on its control channel. The call authenticates with the robot's API key and returns an [`Inference`](#inference) as soon as the run is enqueued; a cold start takes about a minute before the policy is running.

| Arg | Description |
|-----|-------------|
| `prompt` | Natural-language task given to the policy. |
| `track` | Video track the policy watches. |
| `wrist_track` | Optional second (wrist) camera track. |
| `control_channel` | Channel below `{robot}/control/` the policy publishes actions on. |
| `hz` | Action publish rate in hertz. |
| `replan_steps` | Actions consumed from each predicted chunk before replanning. |
| `seconds` | Upper bound on the run's length. |
| `stereo`, `layout`, `flip` | How the policy reads the camera frame. |
| `max_frame_age` | Oldest frame, in seconds, the policy still acts on. |
| `dry_run` | Run the policy without publishing actions to the robot. |

Options are sent only when set, so an unset option takes the service's default. A value the service rejects raises `ValueError` naming the field. The service does not reject a second run on the same robot; start at most one per robot.

```python
with adamo.Robot(name="libero-sim") as robot:
    with robot.inference("pick up the black bowl", "cam") as run:
        while not (status := run.status())["done"]:
            print((status["progress"] or {}).get("state"))
            time.sleep(5)
```

### `Robot.run`

```python
robot.run() -> None
```

Stream the attached tracks until `close()`, a track failure, or Ctrl+C. If a Python-fed track already started the runtime in the background, `run()` waits for that run instead of starting another. Track failures, such as an [encoder error](#encoder-selection), are raised from here.

### `Robot.close`

```python
robot.close() -> None
```

Stop any inference runs, stop the control subscriptions and wait for their threads, and tear down the video runtime and the connection. A failure from a background run that nobody has seen yet is raised from `close()`. Letting the robot be garbage-collected stops everything without waiting.

## `VideoTrack`

Returned from `robot.video()`. Every frame is one tightly packed image of `width × height` pixels in `pixel_format` — exactly `frame_len` bytes.

| Attribute / method | Type | Description |
|--------------------|------|-------------|
| `name` | `str` | Track name. |
| `width`, `height` | `int` | Frame dimensions. |
| `pixel_format` | `str` | Uppercased format name. |
| `frame_len` | `int` | Bytes per frame. |
| `send(frame)` | `None` | Push one frame. |
| `close()` | `None` | End the track. |

`send()` accepts `bytes`, `bytearray`, a `memoryview`, or a C-contiguous NumPy array of `uint8` (`uint16` for `GRAY16_LE`). The frame is copied once; a newer frame replaces one the encoder has not read yet.

- A frame that is not exactly `frame_len` bytes raises `ValueError` before anything is queued.
- A non-contiguous array raises `ValueError` — wrap it in `numpy.ascontiguousarray(frame)`.
- When the encoder or transport fails, the next `send()` raises the stream error.
- After `close()`, or once the robot's run ends, `send()` raises `RuntimeError`. A track cannot outlive the run it streamed in: create a new one instead.

`VideoTrack` supports the context-manager protocol.

Supported `pixel_format` values:

| Format | Bytes per pixel |
|--------|------------------|
| `BGRA`, `RGBA`, `BGRX`, `RGBX` | 4 |
| `RGB`, `BGR` | 3 |
| `YUY2`, `UYVY`, `GRAY16_LE` | 2 |
| `I420`, `NV12`, `NV21` | 1.5 |
| `GRAY8` | 1 |

Format names are case-insensitive.

## Encoder selection

`codec` is `"h264"` (default) or `"av1"`. `encoder` picks the backend for both `attach_video` and `video`:

| `encoder` | Platform | Codecs |
|-----------|----------|--------|
| `None` / `"auto"` | all | Hardware only, for the requested codec. |
| `"nvenc"` | Linux, NVIDIA GPU | H.264, AV1 |
| `"vaapi"` | Linux, AMD or Intel graphics | H.264, AV1 (where the device supports it) |
| `"jetson"` | Jetson Orin (aarch64 build with the `jetson` feature) | H.264, AV1 |
| `"vtenc_h264"` / `"videotoolbox"` | macOS | H.264 |
| `"x264"` | all | H.264, software |

Automatic selection never falls back to software or to another codec: if no hardware encoder can start, the track fails. Set `encoder="x264"` when you deliberately want CPU H.264. Codec-specific aliases must agree with `codec` — `nvav1enc`, for example, requires `codec="av1"`. AV1 is unavailable on macOS.

On a machine with several GPUs, set `ADAMO_VAAPI_DRM_DEVICE=/dev/dri/renderD<N>` to pin the VA-API device.

Encoder failures raise `EncoderSelectionError` (a `RuntimeError`) from `run()`, `close()`, or the next `VideoTrack.send()`. When every attempted backend failed to load its runtime libraries, the subtype `EncoderLibraryError` is raised instead.

| Attribute | Description |
|-----------|-------------|
| `track` | The failing track. |
| `stage` | The pipeline stage that failed. |
| `backend` | The backend being opened. |
| `code` | A machine-readable error code. |
| `attempts` | One dict per backend tried, with `backend`, `message` and `code`; library failures add `libraries` (names and loader diagnostics) and `guidance`. |

```python
try:
    robot.run()
except adamo.EncoderLibraryError as error:
    print(error)  # library names, loader errors, and installation guidance
except adamo.EncoderSelectionError as error:
    print(error.track, error.attempts)
```

AV1 tracks publish low-overhead OBUs with `codec: "av1"` track metadata.

## Adaptive bitrate

With `adaptive_bitrate=True` (the default) the encoder follows the link's congestion forecast between `min_bitrate_kbps` and `max_bitrate_kbps`, starting from `bitrate_kbps`. When several tracks compete for the same link, `bitrate_priority` weights each track's share. `keyframe_distance` is the keyframe interval in seconds.

When the link falls below the bitrate floor, the SDK logs a warning and the picture softens until capacity returns.

## Video routes

`route` selects how a track reaches viewers:

| `route` | Behaviour |
|---------|-----------|
| `"auto"` (default) | Keep the relay path ready while racing authenticated LAN QUIC candidates. Prefer direct when it connects; return to the relay if the direct link closes. |
| `"relay"` | Use only the relay. |
| `"local"` | Require a direct LAN QUIC link; fail with an actionable error when none can be reached. |

`direct_target` adds one explicitly addressed LAN receiver — `192.168.1.50`, `192.168.1.50:17447`, `[fd00::1]:17447`, or `quic/192.168.1.50:17447`. Without a port the SDK dials UDP 17447. `direct_credentials` is a directory holding the `ca.pem`, `client-cert.pem` and `client-key.pem` that authenticate that receiver; when unset, the direct link reuses the organisation certificate minted for the relay session. See [Direct Connection](/direct-connection/).

## `Inference`

A cloud policy run started by `Robot.inference()`.

```python
run.id -> str                   # the inference id assigned by the service
run.status() -> InferenceStatus
run.stop() -> bool              # True when the run had already ended
```

`status()` returns a dict:

| Key | Description |
|-----|-------------|
| `done` | The run has ended — it reached its time limit, was stopped, or failed. Run liveness, never task success. |
| `progress` | The policy loop's progress report while the run is live. |
| `result` | What the run returned, once it ended on its own. |
| `error` | Why the run failed, when it ended with an error. |

A `status()` call can block for up to about 90 s during a cold start and raise `ConnectionError` if the API gives up; retry it.

`stop()` is idempotent. Leaving `with robot.inference(...)`, calling `robot.close()`, or the robot being collected stops the run.

## Concurrency model

- **The constructor and `inference()` block** until the network call completes, releasing the GIL while they wait.
- **Control callbacks run on background threads**, one per `on` subscription. Keep them short; hand work to your main loop.
- **The video runtime runs in its own threads.** `Robot.run()` blocks the calling thread until the run ends; the first `VideoTrack.send()` starts it in the background instead.

## Errors

The SDK raises built-in exception types:

| Exception | Raised when |
|---|---|
| `ConnectionError` | The API key was rejected, or the Adamo API or a relay could not be reached. |
| `TimeoutError` | A network operation timed out. |
| `ValueError` | Bad arguments — unknown options, conflicting sources, wrong frame sizes, values the inference service rejects. |
| `RuntimeError` | State and stream errors — a closed track, changing tracks while running, video pipeline failures. |
| `adamo.EncoderSelectionError` | No requested encoder could start (a `RuntimeError`; see [Encoder selection](#encoder-selection)). |

```python
try:
    robot = adamo.Robot(name="my-robot")
except ConnectionError as error:
    ...  # bad or inactive key — check operate.adamohq.com → Settings → API Keys
```

## Not yet available

These parts of the [legacy 0.4 SDK](/python-sdk/v0-4/) are not in this version yet:

| Legacy API | Status |
|------------|--------|
| `adamo.connect` / `connect_async`, `Session`, `Sample`, `Publisher`, `Subscriber` | Not exposed to Python. |
| `Robot.publish`, `subscribe`, `send`, `recv`, `on_message`, `log`, `session` | Not exposed. Use `Robot.on` for operator control. |
| `Robot.on(broadcast, track, decode=...)` | Replaced by `Robot.on(channel, ...)` with `ControlSample`. |
| `Robot.attach_audio` | Not exposed. |
| `Robot.enable_ros_control`, `attach_video(ros=...)` | Not exposed. |
| `attach_video(shm=..., shm_publish=..., reliability=...)`, `backend="gstreamer"` | Not accepted. Use `device=` or `pipeline=`. |
| `Robot(relay=...)` | Not accepted. |
| `StateStore`, `TaskRunner` | Not exposed. |
| `adamo.operate.control` (`JointState`, `Joy`, …), `adamo.xr` | Not included; control messages arrive decoded as dicts. |
| `adamo.data` (recorded sessions, datasets) | Not included. |
| `AdamoError`, `AuthError`, `NetworkError` | Built-in exceptions are raised instead. |
| `python -m adamo doctor` | Not included. |
