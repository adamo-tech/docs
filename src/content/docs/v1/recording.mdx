The Adamo data service records your robot's cameras and topics. Find your recordings on the [Recordings page](https://operate.adamohq.com/#/recordings) in our web app, and use the Python SDK to list, download and export them as [LeRobot](https://github.com/huggingface/lerobot) datasets.

## Recording a robot

Give the robot a `Recording` to say what to record:

<Tabs syncKey="lang">
<TabItem label="Python" icon="seti:python">

```python
import json
import adamo
from i2rt.robots.get_robot import get_yam_robot

recording = adamo.Recording(
    adamo.ControllerMask.HUMAN | adamo.ControllerMask.POLICY,
    mode=adamo.RecordingMode.Episodes(frame_rate=adamo.FrameRate.Fixed(30)),
    topics=["left/joint_pos", "left/joint_cmd"],
)
robot = adamo.Robot(name="my-arm", record=recording)
joint_pos = robot.session.publisher("my-arm/left/joint_pos", reliable=True)
joint_cmd = robot.session.publisher("my-arm/left/joint_cmd", reliable=True)

arm = get_yam_robot(channel="can0")
command = arm.get_joint_pos()
for _ in adamo.Rate(30):
    arm.command_joint_pos(command)
    joint_pos.put(json.dumps(arm.get_joint_pos().tolist()).encode())
    joint_cmd.put(json.dumps(command.tolist()).encode())
```

</TabItem>

```rust
use std::num::NonZeroU32;
use std::time::Duration;
use adamo::{ControllerMask, FrameRate, Mode, PublisherOptions, Rate, Recording, Robot};

let robot = Robot::new_default("ak_...", Some("my-arm"))?.with_recording(Recording {
    controller_mask: ControllerMask::HUMAN | ControllerMask::POLICY,
    mode: Mode::Episodes { frame_rate: FrameRate::Fixed { rate: NonZeroU32::new(30).unwrap(), gop: NonZeroU32::new(2).unwrap() }, min_duration: Duration::from_secs(2) },
    topics: vec!["left/joint_pos".to_owned(), "left/joint_cmd".to_owned()],
    ..Recording::default()
});
let joint_pos = robot.publisher("my-arm/left/joint_pos", PublisherOptions { reliable: true, ..PublisherOptions::default() })?;
let joint_cmd = robot.publisher("my-arm/left/joint_cmd", PublisherOptions { reliable: true, ..PublisherOptions::default() })?;

let mut rate = Rate::new(30.0);
loop {
    arm.command_joint_positions(&command);
    joint_pos.put(&serde_json::to_vec(&arm.joint_positions())?)?;
    joint_cmd.put(&serde_json::to_vec(&command)?)?;
    rate.sleep();
}
```

This records one episode per task, at 30 frames a second, ready for training. In Rust, `arm` and `command` stand for your arm's driver and the command you send it. `adamo.Recording()` on its own records continuously, with each camera's video as the robot sent it.

### When it records

Record only the time you need. `controller_mask` picks it:

| Flag | Records while |
|------|---------------|
| `HUMAN` | A teleoperator controls the robot. |
| `POLICY` | A policy controls the robot. |
| `UNATTENDED` | Nobody controls the robot. |

The default is `HUMAN | POLICY`. To record regardless of who is in control, call `robot.start_recording()`, then `robot.stop_recording()`.

### Modes

Adamo supports three recording modes, set with `mode`:

| Mode | Description |
|---|---|
| `RecordingMode.Episodes(frame_rate, min_duration=2.0)` | Creates one recording file per episode, from the start of a task to its end. Tasks shorter than `min_duration` seconds are left out. |
| `RecordingMode.Continuous(frame_rate, post_roll=0.0, idle_timeout=120.0)` (default) | Creates one recording file per stretch of recorded time, with `post_roll` seconds after it. |
| `RecordingMode.Interventions(pre_roll=5.0, post_roll=0.0, frame_rate)` | Creates one recording file whenever the controller changes, with `pre_roll` seconds before it and `post_roll` seconds after. |

- In Continuous mode, a teleoperator's time in control after their last input is left out once `idle_timeout` seconds pass without another. `idle_timeout=None` keeps it.
- Files are cut into parts after `max_duration` seconds (default 1800) or `max_size` bytes (default 1.5 GB).

### Frame rate

A training example pairs a picture from every camera with the state and action of the same moment, so training needs every camera on one clock. `frame_rate` sets that clock:

| Frame rate | Video in the file |
|---|---|
| `FrameRate.Raw()` (default) | Each camera as the robot sent it, at its own rate. |
| `FrameRate.Fixed(rate, gop=2)` | Every camera on one clock of `rate` frames a second. |
| `FrameRate.Max(gop=2)` | Every camera on one clock at the rate of the fastest camera. |

To record for training, give a clock:

```python
adamo.RecordingMode.Episodes(frame_rate=adamo.FrameRate.Fixed(30))
```

The data service then encodes every camera onto that clock as it records, so frame *k* of each camera is at *k* / `rate` seconds. `gop` is the number of frames between keyframes (see [Reducing recording size](#reducing-recording-size)).

`FrameRate.Raw()` is usually the most compact way to store video, but it must be put on one clock and encoded again before training, which `Recordings.export` does for you.

In Rust, the choices are `FrameRate::Raw`, `FrameRate::Fixed { rate, gop }` and `FrameRate::Max { gop }`.

### Topics

`topics` adds the data you want to record alongside the cameras and controls, such as joint states and actions. Name each topic relative to the robot: `"left/joint_pos"` records `my-arm/left/joint_pos`.

- Each value is stamped with the time it was sent, on the same clock as the video.
- Each file starts with the latest value of every topic, so a topic sent once is in every file.
- Payloads are recorded as they are. JSON numbers and arrays of numbers export directly. Anything else needs a [decoder](#decoders).
- Cameras and the `control/`, `tasks/` and `recording/` keys are always recorded. Naming one of them in `topics` warns and is ignored.

### ROS topics

If your robot already runs [ROS](/v1/ros/), record its topics directly instead of publishing them again. `record_ros` records native ROS topics as JSON:

```python
robot.record_ros(["/joint_states", "/gripper/state"], max_age=1.0)
```

- `/joint_states` is recorded as `joint_states`, and its fields export as `joint_states.position`.
- Messages older than `max_age` seconds are skipped.
- Custom message types need their `.msg` definitions: `definitions={"package/msg/Type": msg_text}`.
- Call it once, with every ROS topic to record.

### Audio

Record audio to train models on sound, such as voice models. `record_audio=True` records every [audio track](/v1/audio/) on the robot: its own tracks, and each operator's microphone as `operator-{session id}`. It is off by default.

Audio keeps its own timing. Each track is stored as the Opus packets it sent, at their capture times on the video's clock, under `audio/{track}`. A recording lists its tracks in `audio_tracks`. See [Exporting audio](#exporting-audio) to decode them.

### Tasks

Tasks turn teleoperation into labelled episodes, each with a prompt and an outcome. In Episodes mode, files follow the tasks the operator runs from the web app's task list (Settings, Tasks, "Show task list"). Starting a task opens a file. Stopping it with Success or Failure, or aborting it, closes the file with that outcome. See [Task Signals](/v1/control/#task-signals).

### Reducing recording size

To store more hours of data:

- **Raise the GOP.** Keyframes are the largest frames, so `FrameRate.Fixed(30, gop=30)` makes much smaller files. A small `gop` lets a training loader jump to any frame quickly, since a frame far from its keyframe takes longer to decode on its own.
- **Leave out unattended time.** Keep `UNATTENDED` out of `controller_mask`, and call `robot.stop_recording()` once you no longer need a recording you started.

## Finding recordings

Select the recordings to download, export or train on. `adamo.Recordings` reads your organization's recordings, using your `ADAMO_API_KEY`:

```python
from datetime import datetime, timedelta, timezone
import adamo

client = adamo.Recordings()
recordings = client.list(
    start=datetime.now(timezone.utc) - timedelta(days=7),
    devices=["my-arm"],
    tasks=["PickUpCube"],
    tags=["data_collection"],
)
client.download(recordings, "recordings")
```

`list` also filters by `end`, `controllers`, `sessions`, `folder`, and `search` over names and notes. Each recording's `frame_rate` is the clock it was saved on.

The Copy Query button on the [Recordings page](https://operate.adamohq.com/#/recordings) writes this code for the current filters.

## Exporting to LeRobot

Export your recordings to train outside Adamo, with LeRobot's training scripts or your own code. To train on Adamo, skip the export and use [`adamo.Dataset`](/v1/training/#datasets).

`Recordings.export` writes recordings as a LeRobot dataset, one episode per recording, and returns the `LeRobotDataset`. It needs `pip install "adamo[export]"` and Python 3.12 or newer.

```python
dataset = client.export(recordings, adamo.Export(
    state=["left/joint_pos", "left/gripper_pos"],
    action=["left/joint_cmd"],
    outcomes=["success"],
    tasks={"PickUpCube": "Pick up the cube."},
))
```

| `Export` field | Description |
|-------|-------------|
| `state`, `action` | Recorded topics, or fields of a JSON topic such as `"arm/state.position"`, concatenated in order. Each frame holds the latest value sent at or before it. |
| `outcomes` | Keeps only episodes that ended this way: `"success"`, `"failure"` or `"abort"`. Every outcome is kept by default. |
| `tasks` | Maps each task to its prompt, and keeps only those tasks. Without it, every task is kept, and `PickUpCube` becomes the prompt `"Pick up cube."`. Recordings without a task are always kept, with an empty prompt. |
| `images` | The camera tracks to keep, such as `["front", "zed.left"]`. Every camera is kept by default. See [Choosing cameras](/v1/training/#choosing-cameras). |
| `frame_rate` | The dataset's frames per second. Defaults to the rate the recordings were saved at. |

The Export Dataset button on the [Recordings page](https://operate.adamohq.com/#/recordings) writes this code for the current filters.

### Output folder

The dataset goes to `lerobot-{hash}` in the current folder, or to `output_folder=`. The hash covers the recordings, the export and the decoders, so running the same export again opens the existing dataset instantly.

The recordings are downloaded to a temporary folder, or to `download_folder=` to keep them.

### Decoders

Binary payloads, such as packed structs or MessagePack, are smaller to send than JSON, but the export cannot read them on its own. Give each such topic a decoder that turns a payload into numbers. For a fixed binary layout, `adamo.Struct` takes a [`struct` format](https://docs.python.org/3/library/struct.html#format-strings):

```python
dataset = client.export(recordings, export, decoders={
    "proprioception/joints": adamo.Struct(">8x14f"),  # skip an 8-byte timestamp, then 14 big-endian float32s
})
```

Any function of the payload's bytes also works. Only an `adamo.Struct` decodes a [training dataset](/v1/training/#datasets), which is built on Adamo.

A topic without its decoder stops the export before it downloads anything, with a `ValueError` that names the topic.

## Exporting audio

To use the audio you recorded with `record_audio=True`, export it as standard audio files. `Recordings.export_audio` writes one file per track:

```python
files = client.export_audio(recordings, "audio", tracks=["mic", "operator-*"])
print(files[0])  # audio/my-arm/{name}/mic.wav
```

- Each track goes to `audio/{device}/{name}/{track}.wav`, at 48 kHz. `format=` also takes `"flac"` and `"mp3"`.
- `tracks` keeps the tracks that match any pattern: `"mic"` is the robot's track of that name, and `"operator-*"` every operator's microphone. Every track is kept by default.
- A pattern that matches no track warns, and lists the tracks the recordings have. When no pattern matches at all, the export raises a `ValueError` before downloading anything.
- Each file starts at the recording's first video frame, with silence wherever the track sent nothing, so the tracks line up with each other and with the video.

Recordings without a matching track are skipped. On the [Recordings page](https://operate.adamohq.com/#/recordings), tick Export audio to add this call to the Export Dataset code.
