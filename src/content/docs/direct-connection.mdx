---
title: "Direct Connection (P2P)"
description: "Firewall requirements for direct connections to robots on your local network"
---

The app connects directly to a nearby robot automatically when it can reach it. WebSocket connections use local TCP; WebTransport connections use local UDP. If the direct connection is unavailable, the app continues through the relay.

## Open the robot's firewall port

On the **computer running the robot publisher**, allow incoming connections from your operator's LAN to the publisher's local port:

- **TCP** for WebSockets.
- **UDP** for WebTransport.

Use the publisher's actual local port; it is not always `17447` and may change after a restart. Python publishers expose it as `robot.local_port`; Rust publishers expose it as `robot.session().local_port()`.

For an active UFW firewall, these example rules allow both transports from `192.168.1.0/24` to port `17447`. **Replace the subnet and port with your values:**

```sh
sudo ufw allow proto tcp from 192.168.1.0/24 to any port 17447
sudo ufw allow proto udp from 192.168.1.0/24 to any port 17447
sudo ufw status
```

For another firewall, allow the equivalent inbound ports from your LAN. No public router port forwarding is needed.

Browser local-network permission does not open the robot's firewall. A connection on the publisher computer can work while a phone or another computer is blocked. Check the firewall and Wi-Fi device isolation if only same-computer connections work.
